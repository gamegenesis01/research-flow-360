# Publishing an issue of Research Flow 360

Every issue is one text file in `issues/`. Muse proposes it; the editor approves it; the site updates itself.

```
Muse writes issues/2026-11-30.md  →  opens a pull request  →  "Check issue" runs
        →  editor reads and taps Merge  →  site rebuilds and publishes (about 1 minute)
```

After merging, the issue becomes **Today's brief** (if it's the newest Daily Brief), gets a permanent
page at `briefs/2026-11-30.html`, and appears at the top of the **Archive**. The live market snapshot
keeps updating on top of today's brief.

## 1. Writing the issue (Muse)

Copy `issues/TEMPLATE.md` to `issues/YYYY-MM-DD.md` and fill it in. A second issue on the same day
(for example a breaking alert) adds a word: `issues/2026-11-30-alert.md`.

Header fields:

| Field | Required | Values |
| --- | --- | --- |
| `date` | yes | `YYYY-MM-DD`, same as the file name |
| `type` | no (default `daily`) | `daily`, `alert`, `wrap`, `inside` |
| `title` | yes | Put the orange part between stars: `The Fed holds, *and chips lead again.*` |
| `summary` | recommended | One sentence; shown in the archive and on the home page |
| `read_time` | no | Minutes, for example `5` |
| `sample` | no | `true` only for examples |

Sections the site understands (any other `## Section` is shown as a plain section):

| Section | Format |
| --- | --- |
| `## The big story` | `### Headline`, paragraphs, `> Why it matters: ...`, `Source: [name](https://...)` |
| `## Quick hits` | Each story: `### [Tag] Headline`, one or two sentences, `Source: ...` |
| `## Chart of the day` | `### Title`, then 2 to 8 lines like `- Mon: 4.11`, optional `base:`, `unit:`, `caption:` |
| `## What to watch` | Lines like `- 8:30 am | Weekly jobless claims (Labor Department)` |
| `## Sponsor` | Leave out when there is no sponsor |

Text can use `**bold**`, `*emphasis*` and `[links](https://...)`. HTML is shown as plain text.

Editorial rules for every issue: a source on every story; other outlets summarized in our own words and
linked, never copied; Accel Media Ltd labelled as "our sister company"; no buy or sell recommendations;
never mention Accel's live positions.

## 2. Proposing it (Muse, through the GitHub API)

Muse needs a **fine-grained personal access token** limited to this repository (see section 4).
With the token in `GITHUB_TOKEN`:

```bash
REPO=gamegenesis01/research-flow-360
DATE=2026-11-30
BRANCH=issue-$DATE
API=https://api.github.com/repos/$REPO
AUTH="Authorization: Bearer $GITHUB_TOKEN"

# a) branch from main
SHA=$(curl -s -H "$AUTH" $API/git/ref/heads/main | jq -r .object.sha)
curl -s -X POST -H "$AUTH" $API/git/refs -d "{\"ref\":\"refs/heads/$BRANCH\",\"sha\":\"$SHA\"}"

# b) add the issue file
CONTENT=$(base64 -w0 issues/$DATE.md)
curl -s -X PUT -H "$AUTH" $API/contents/issues/$DATE.md \
  -d "{\"message\":\"Issue $DATE\",\"branch\":\"$BRANCH\",\"content\":\"$CONTENT\"}"

# c) open the pull request for the editor
curl -s -X POST -H "$AUTH" $API/pulls \
  -d "{\"title\":\"Daily Brief $DATE\",\"head\":\"$BRANCH\",\"base\":\"main\",\"body\":\"Ready for review.\"}"
```

The **Check issue** job runs on the pull request within a minute. A red ✗ means the file needs fixing;
its log says exactly what is wrong (for example "date in the header must match the file name").

## 3. Approving it (editor)

1. Open the pull request in the GitHub app or on github.com (you get a notification).
2. Open **Files changed** and read the issue.
3. If it needs a change, edit the file right there, or comment and let Muse fix it.
4. When the check is green ✓, tap **Merge pull request**.

The site publishes about a minute later. To correct a published issue, edit its file in `issues/`
the same way; the page and archive update automatically.

## 4. One-time setup: Muse's access token

1. GitHub → **Settings → Developer settings → Personal access tokens → Fine-grained tokens →
   Generate new token**.
2. **Repository access:** Only select repositories → `research-flow-360`.
3. **Permissions → Repository:** Contents **Read and write**, Pull requests **Read and write**.
   Leave everything else at No access.
4. Give the token to Muse through its secure settings (never paste it in chat or in a file).
5. Optional but recommended: **Settings → Branches → Add rule for `main`** → Require a pull request
   before merging. Then nothing reaches the site without the editor's approval.

## Don't edit the HTML files

`index.html`, `brief.html`, `archive.html`, `about.html`, `advertise.html`, `404.html` and `briefs/` are
generated by `scripts/build_site.py` on every publish, so direct edits to them are overwritten. Edit
`templates/` (home, about, advertise) or `issues/` instead.
